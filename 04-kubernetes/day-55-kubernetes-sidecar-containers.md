# Day 55: Kubernetes Sidecar Containers

## Question

We have a web server container running the nginx image. The access and error logs generated by the
web server are not critical enough to be placed on a persistent volume. However, Nautilus
developers need access to the last 24 hours of logs so that they can trace issues and bugs.
Therefore, we need to ship the access and error logs for the web server to a log-aggregation
service. Following the separation of concerns principle, we implement the Sidecar pattern by
deploying a second container that ships the error and access logs from nginx. Nginx does one
thing, and it does it well, serving web pages. The second container also specializes in its task,
shipping logs. Since containers are running on the same Pod, we can use a shared emptyDir volume
to read and write logs.

1. Create a pod named `webserver`.
2. Create an `emptyDir` volume named `shared-logs`.
3. Create a regular container in the `webserver` pod from the `nginx:latest` image named
   `nginx-container`, and an init container from the `ubuntu:latest` image named
   `sidecar-container`, configured as a native sidecar by setting its `restartPolicy` to `Always`.
4. Add the following command to the `sidecar-container`
   `"sh","-c","while true; do cat /var/log/nginx/access.log /var/log/nginx/error.log; sleep 30; done"`
5. Mount the `shared-logs` volume in both containers at `/var/log/nginx`. Ensure all containers
   are in a running state.

> `Note:` The `kubectl` utility on the `jump-host` has been configured to work with the Kubernetes
> cluster.

## Solution

Create a manifest on the jump host:

```bash
vi pod.yaml
```

Add the following content:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: webserver
spec:
  initContainers:
    - name: sidecar-container
      image: ubuntu:latest
      restartPolicy: Always
      command:
        - sh
        - -c
        - while true; do cat /var/log/nginx/access.log /var/log/nginx/error.log; sleep 30; done
      volumeMounts:
        - name: shared-logs
          mountPath: /var/log/nginx
  containers:
    - name: nginx-container
      image: nginx:latest
      volumeMounts:
        - name: shared-logs
          mountPath: /var/log/nginx
  volumes:
    - name: shared-logs
      emptyDir: {}
```

Create the Pod and confirm both containers are running:

```bash
kubectl apply -f pod.yaml
# pod/webserver created

kubectl wait --for=condition=Ready pod/webserver --timeout=60s
# pod/webserver condition met

kubectl get pod webserver
# NAME        READY   STATUS    ...
# webserver   2/2     Running   ...
```

Read the sidecar's output. It prints the Nginx access and error logs every 30 seconds:

```bash
kubectl logs -f webserver -c sidecar-container
```

## Why

| Field | Why |
|:--|:--|
| `initContainers` + `restartPolicy: Always` | Kubernetes' native sidecar form. Without the restart policy it would finish before nginx starts. |
| `shared-logs` on `/var/log/nginx` | Replaces nginx's log directory with the shared volume so the sidecar can read it. |
| `while true; do ... sleep 30; done` | The 30-second interval the task asks for. |
| `kubectl logs -c sidecar-container` | Follows only the sidecar's output in a two-container Pod. |

## Notes

- A native sidecar goes under `initContainers`, not alongside the app container.
- The first loop may report the log files missing. nginx creates them at startup and the loop retries.
- `emptyDir` is temporary, which is exactly what "no persistent storage" asks for.
